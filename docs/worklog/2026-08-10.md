## Decisions made
- Verify with `mongodb-memory-server` instead of Docker — Docker Desktop failed to start in this
  environment and debugging a broken Docker install wasn't the goal; `mongodb-memory-server`
  gives a real `mongod` without it. Rules out relying on Docker for local dev until someone
  fixes/reinstalls it — worth keeping the memory-server path available for tests either way.

## Problems hit & how they were solved
- Docker Desktop wouldn't start (`Docker Desktop is unable to start`, backend named-pipe
  unreachable) even after launching it and waiting ~3 minutes → switched to
  `mongodb-memory-server` rather than debug a GUI app's startup headlessly.
- `mongodb-memory-server`'s ESM import failed when the verification script lived outside
  `server/` (Node resolves bare specifiers relative to the importing file's own `node_modules`
  ancestry, not `cwd`) → moved the script inside `server/`, ran it, deleted it after.

  a real browser — fell back to confirming the dev server serves `/`, `/login`, and every module
  in the app's import graph with `200` and no Vite transform errors. This is real dev-server
  verification, but not the same as watching it render — flagging that gap rather than implying
  full visual confirmation.
