## Decisions made

- **Split the migration commit from the render.yaml disk commit** — even though both touched
  `render.yaml`, keeping the disk change isolated meant it could be (and was) reverted on its own
  without touching the unrelated, already-tested migration.
- **Stayed on `plan: free` in `render.yaml`, dropped the uploads disk** — user's call given the
  cost tradeoff; report uploads remain ephemeral on Render until upgraded. Already flagged as a
  known gap in `docs/PROGRESS.md`.
- **Render before Vercel** — `VITE_API_URL` needs a real server URL, and `CLIENT_ORIGIN` needs a
  real client URL, so deploying either first alone can't be fully configured; documented the
  two-pass order (Render → note URL → Vercel with that URL → back to Render for `CLIENT_ORIGIN`)
  rather than guessing a placeholder.
